# nodeforge
 
Интерактивный скрипт-меню для **первичной настройки и харденинга сервера** под
ноду **Remnawave** (`remnanode`). Один файл на bash, без зависимостей:
запустил — выбрал пункты — готово.
 
```
              _      __
 _ _  ___  __| |___ / _|___ _ _ __ _ ___
| ' \/ _ \/ _` / -_)  _/ _ \ '_/ _` / -_)
|_||_\___/\__,_\___|_| \___/_| \__, \___|
                               |___/
   harden · configure · remnawave node
```
 
> ⚠️ Скрипт меняет системные настройки (SSH, ядро, фаервол, docker-compose).
> Читайте, что делает каждый пункт. Все рискованные правки делаются с бэкапом и
> откатом, но ответственность за запуск на вашем сервере — на вас.
 
---
 
## Возможности
 
- **SSH-харденинг**: смена порта, создание пользователя с `sudo NOPASSWD`,
  установка ключа, запрет логина root и парольной аутентификации. ufw ставится
  автоматически, если его нет.
- **fail2ban** с учётом текущего SSH-порта.
- **Ядро XanMod** с выбором из доступных пакетов (рекомендация по уровню psABI
  процессора) и **BBR** (`fq` + `bbr`).
- **netbird** (mesh VPN) и **remnanode** (интерактивный установщик ноды).
- **Настройка ноды**: блокировка RU-контента (geoip/geosite + cron-обновление),
  ротация логов (logrotate + zstd), XHTTP-location в nginx, апгрейд nginx
  1.28 → 1.30.1.
- **Сервис**: перезапуск контейнеров, диагностика ноды, набор внешних
  проверок/бенчмарков (блокировки, регион по IP, DPI, скорость, CPU),
  самообновление скрипта.
---
 
## Требования
 
- Ubuntu 22.04 / 24.04 (или другой Debian-подобный дистрибутив с `apt`).
- Доступ **root** (или `sudo`).
- `bash`, `curl`/`wget` (есть по умолчанию).
- Для пунктов настройки ноды — уже установленный `remnanode`
  (`docker compose` в `/opt/remnanode`).
---
 
## Запуск
 
Одной командой (тянет свежую версию и сразу открывает меню):
 
```bash
bash <(curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup)
```
 
Скрипту нужен root. Если вы не под root — скачайте и запустите через sudo
(`sudo bash <(…)` иногда даёт проблемы с правами на дескриптор):
 
```bash
curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup -o /tmp/setup && sudo bash /tmp/setup
```
 
В меню можно вводить **несколько номеров через пробел**, например `1 2`.
 
Отключить цвета (для логов / простого терминала):
 
```bash
NO_COLOR=1 bash <(curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup)
```

## Пункты меню
 
**До перезагрузки (совместимы в одном проходе)**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 1 | SSH-харденинг | Порт, пользователь + `sudo NOPASSWD`, SSH-ключ, запрет root и паролей. Авто-установка ufw + правило `allow <порт>/tcp`. |
| 2 | fail2ban | Защита от брутфорса, берёт текущий SSH-порт. |
 
**Ядро (точка перезагрузки)**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 3 | Ядро XanMod | Список доступных пакетов XanMod + выбор. После установки нужен `reboot`. |
 
**После перезагрузки**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 4 | BBR | Включает `fq` + `bbr` (без вопросов). |
| 5 | netbird | Установка mesh-VPN netbird. |
| 6 | remnanode | Интерактивный установщик ноды Remnawave. |
 
**После ноды (управление remnanode)**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 7 | RU-блокировка | Копирует штатные geoip/geosite, качает RU-списки (runetfreedom), bind-mount в `remnanode`, ставит cron-обновление. Печатает JSON `outbounds`/`routing` для вставки в панель. |
| 8 | Логи ноды | logrotate + zstd, том логов у `remnanode`. Напоминает добавить блок `log` в Config Profile панели. |
| 9 | XHTTP | Вставляет `location /<путь>/` в `nginx.conf` (ровные отступы, идемпотентно), `nginx -t` + откат при ошибке. |
| 10 | nginx 1.28 → 1.30.1 | Проверяет версию образа; если 1.28 — спрашивает и обновляет (закрывает CVE), с бэкапом и откатом. |
| 11 | Перезапуск контейнеров | `docker compose restart` / пересоздать (`down && up -d`) стек ноды, либо перезапуск всех контейнеров на хосте. |
 
**Диагностика / сервис**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 12 | Диагностика ноды | Запуск внешнего скрипта [`Case211/node-diagnostic`](https://github.com/Case211/node-diagnostic). |
| 13 | Проверки и бенчмарки | Подменю: IP.Check.Place, IP-регион (ipregion), CensorCheck (DPI), Instagram audio, bench.sh / tlab, YABS, sysbench CPU. |
| 14 | Обновить скрипт | Скачивает свежую версию с GitHub и перезапускается. |
 
**Группы**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 15 | Всё ДО ядра | Запускает пункты 1 + 2. |
| 16 | Всё ПОСЛЕ ребута | Запускает пункты 4 + 5 + 6. |
| 0 | Выход | |

## Рекомендуемый порядок
 
1. **До перезагрузки** — пункт `15` (= 1 + 2): SSH-харденинг и fail2ban.
2. **Ядро** — пункт `3`, затем `reboot`.
3. **После ребута** — пункт `16` (= 4 + 5 + 6): BBR, netbird, remnanode.
4. **Настройка ноды** — пункты `7`–`11` по необходимости (плюс шаги в панели, см. ниже).
5. **Проверка** — пункты `12`/`13`.
---
 
## Шаги в панели Remnawave
 
Конфиг Xray в Remnawave единый и пушится на все ноды, поэтому часть шагов
**нельзя автоматизировать с ноды** — скрипт делает серверную часть и подсказывает,
что доделать в панели:
 
- **После пункта 7 (RU-блокировка)** — в разделе *Xray Config* заменить блоки
  `outbounds` и `routing` на JSON, который печатает скрипт, и сохранить.
- **После пункта 8 (Логи)** — в *Config Profile* ноды добавить блок `log` с путями
  `/var/log/remnanode/access.log` и `/var/log/remnanode/error.log`, иначе логи не
  появятся.

## Безопасность
 
- **В репозитории нет секретов.** Пароли, SSH-ключи, ключи netbird и т.п. вводятся
  при запуске через `read` и нигде не сохраняются (в историю shell не попадают).
- **Бэкапы и откат.** Правки `sshd_config`, `nginx.conf` и `docker-compose.yml`
  делаются с резервной копией `.bak` и проверкой (`sshd -t`, `nginx -t`,
  `docker compose pull`); при ошибке изменения откатываются.
- **ufw не включается автоматически.** Скрипт ставит ufw и добавляет правило
  `allow`, но **не** делает `ufw enable` — чтобы не отрезать себе доступ. Включайте
  фаервол вручную, убедившись, что нужные порты разрешены.
- **NAT-VPS.** Если у провайдера внешний SSH-порт проброшен на внутренний `:22`
  (общий IP, «выделенного IP нет»), **не меняйте SSH-порт** — иначе проброс
  перестанет работать и вы потеряете доступ. На таких VPS оставляйте порт 22 и
  подключайтесь по внешнему проброшенному порту.
- **Внешние скрипты.** Пункты 12 и 13 запускают сторонний код с других доменов.
  Запускайте осознанно.
---
 
## Обновление
 
Меню → пункт **14**. Скрипт скачает свежую версию из репозитория и перезапустится.
Либо просто запустите команду из раздела «Запуск» ещё раз — она всегда тянет
актуальную версию.
