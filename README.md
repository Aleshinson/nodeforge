# nodeforge
 
Интерактивный скрипт-меню для **первичной настройки и харденинга сервера** под
ноду **Remnawave** (`remnanode`). Один файл на bash, без зависимостей:
запустил — выбрал пункты — готово.
 
```
              _      __
 _ _  ___  __| |___ / _|___ _ _ __ _ ___
| ' \/ _ \/ _` / -_)  _/ _ \ '_/ _` / -_)
|_||_\___/\__,_\___|_| \___/_| \__, \___|
                               |___/
   harden · configure · remnawave node
```
 
> ⚠️ Скрипт меняет системные настройки (SSH, ядро, фаервол, сеть, docker-compose).
> Читайте, что делает каждый пункт. Все рискованные правки делаются с бэкапом и
> откатом, но ответственность за запуск на вашем сервере — на вас.
 
---
 
## Возможности
 
- **SSH-харденинг**: смена порта, пользователь с `sudo NOPASSWD`, ключ, запрет
  логина root и паролей.
- **node-accelerator**: ядро XanMod (BBRv3) + сетевой тюнинг (`optimize`) и
  единый фаервол nftables `na_filter` + CrowdSec + блоклисты (`protect`). ufw
  выключается — фаервол один.
- **Служебные порты только для панели**: порт ноды и порт агента Beszel
  принимают соединения только с IP панели (в т.ч. через netbird).
- **MTU**: замер пути до интернета и выставление MTU интерфейса, если хостер
  пускает трафик через туннель и путь уже 1500.
- **Аудит ноды**: MTU, зависания ВМ у хостера, GeoIP, маршруты, слетевший
  фаервол, открытые порты, logrotate, мёртвые location, сертификат — и починка
  найденного прямо из аудита, по выбору.
- **netbird** (mesh VPN), **remnanode**, **Beszel** (мониторинг).
- **Настройка ноды**: блокировка RU-контента (geoip/geosite + cron), ротация
  логов (logrotate + zstd), XHTTP/gRPC-location в nginx, апгрейд nginx,
  SNI-проверка mTLS.
- **Сервис**: перезапуск контейнеров, внешние диагностики и бенчмарки, шейпер,
  блок РФ-госсетей, SSH-уведомления в Telegram, бэкап конфигов, fleet-sync,
  самообновление скрипта.
---
 
## Требования
 
- Ubuntu 22.04 / 24.04 (или другой Debian-подобный дистрибутив с `apt`).
- Доступ **root** (или `sudo`).
- `bash`, `curl`/`wget` (есть по умолчанию).
- Для пунктов настройки ноды — уже установленный `remnanode`
  (`docker compose` в `/opt/remnanode`).

## Запуск
 
Одной командой (тянет свежую версию и сразу открывает меню):
 
```bash
bash <(curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup)
```
 
Скрипту нужен root. Если вы не под root — скачайте и запустите через sudo
(`sudo bash <(…)` иногда даёт проблемы с правами на дескриптор):
 
```bash
curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup -o /tmp/setup && sudo bash /tmp/setup
```
 
В меню можно вводить **несколько номеров через пробел**, например `1 2`.
 
Отключить цвета (для логов / простого терминала):
 
```bash
NO_COLOR=1 bash <(curl -Ls https://raw.githubusercontent.com/Aleshinson/nodeforge/main/setup)
```

## Пункты меню
 
**Базовые шаги**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 1 | SSH-харденинг | Порт, пользователь + `sudo NOPASSWD`, SSH-ключ, запрет root и паролей. Если `na_filter` уже поднят — переприменяет его, когда `sshd` слушает новый порт. |
| 2 | optimize | node-accelerator: ядро XanMod (BBRv3), sysctl, RPS/RFS, swap. После — `reboot`. |
| 3 | protect | node-accelerator: `na_filter` + CrowdSec + блоклисты. Спрашивает IP панели. В конце — подтверждение входа в новом окне (см. «Сейфти-таймер»). |
| 4 | netbird | Установка/обновление mesh-VPN и подключение по setup-key. |
| 5 | remnanode | Интерактивный установщик ноды; гасит ufw, который он включает. |
 
**Настройка ноды**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 6 | RU-блокировка | Штатные + RU geoip/geosite (runetfreedom), bind-mount в `remnanode`, cron-обновление. Печатает JSON `outbounds`/`routing` для панели. |
| 7 | Логи ноды | logrotate + zstd для `/var/log/remnanode`. Забирает эту маску у станзы node-accelerator — иначе две станзы на один файл и logrotate падает. |
| 8 | XHTTP | `location /<путь>/` в `nginx.conf`, `nginx -t` + откат. |
| r | gRPC | То же для gRPC (сокет `xrgrpc`). |
| 9 | nginx 1.28 → 1.30.x | Проверяет образ, обновляет с бэкапом и откатом. |
| 10 | Перезапуск контейнеров | `restart` / пересоздать стек ноды или все контейнеры. |
 
**Мониторинг (Beszel)**
 
| № | Пункт | Что делает |
|---|-------|------------|
| 11 | Подключить агент | Ставит `beszel-agent`; порт агента открывается **только для IP панели** (хаб стоит у неё). |
| 12 | Обновить Beszel | Агент и/или хаб (бинарь или docker). |
 
**Диагностика / сервис**
 
| № | Пункт | Что делает |
|---|-------|------------|
| a | Аудит ноды | Встроенный, ~1 мин: проверка + починка найденного по выбору. См. ниже. |
| 13 | Диагностика | Подменю: node-diagnostic / node-accelerator diagnose / аудит. |
| 14 | Проверки и бенчмарки | IP-регион, CensorCheck, IP.Check.Place, IPQuality, iPerf3 до РФ, YABS, bench.sh, sysbench. |
| 15 | Обновить скрипт | Свежая версия с GitHub + перезапуск. |
 
**Дополнительно**
 
| № | Пункт | Что делает |
|---|-------|------------|
| p | Порты | Что слушает сервер, реестр портов, добавить/убрать/применить. |
| f | Починить фаервол | Переприменить `na_filter` по реестру (+ IP панели в whitelist). |
| k | Порты для панели | Порт ноды и `PANEL_PORTS` (beszel) — только с IP панели. |
| m | MTU | Замер пути MTU и выставление MTU интерфейса — сейчас и после ребута. |
| s | Шейпер | Лимиты скорости на уровне ноды. |
| g | Блок РФ-госсетей | Отдельная nft-таблица, drop входящих с госсетей. |
| n | SSH-уведомления | Telegram при входе по SSH. |
| b | Бэкап конфигов | Один архив: sshd, реестр, compose/nginx ноды, logrotate, сеть, nft, cron. |
| u | Обновить списки | geo / блоклисты / госсети + самолечение cron. |
| w | netbird: обновить | apt-обновление демона. |
| l | Fleet-sync | Ноды флота держат IP друг друга в whitelist (через API панели). |
| v | SNI-проверка ноды | `SNI_VERIFICATION` для mTLS панель→нода (node ≥ 3.4). |

## Рекомендуемый порядок
 
`16` → `reboot` → `17` → `18` → `19` → `m` → `a`.
 
Аудит в конце покажет, всё ли встало: фаервол загружен и в автозагрузке,
служебные порты закрыты, MTU совпадает с путём, logrotate без ошибок.

## Аудит ноды (пункт `a`)
 
Проверка только читает. Ловит то, что тихо портит ноду и не видно в панели:
 
- **Система** — CPU steal; зависания ВМ у хостера (soft lockup, RCU stall,
  `TX timeout` в ядре) с временем; OOM; свободная память, swap, нагрузка;
  упавшие сервисы; диск; NTP; ожидание перезагрузки.
- **Сеть и MTU** — `bbr`/`fq`; путь MTU до четырёх точек против MTU интерфейса;
  `tcp_mtu_probing`; conntrack (заполнение и таймаут простаивающих TCP — короткий
  рвёт молчащие мессенджеры); повторные отправки TCP; потери в softnet; потери
  UDP на приёме (звонки); сломанный IPv6; скорость системного DNS (им резолвит Xray).
- **Маршруты** — задержка, джиттер и потери до Cloudflare, Google и Яндекса
  (Москва). До Cloudflare из дата-центра обычно <10 мс: больше 30 — маршрут
  кружной.
- **GeoIP** — страна по ipinfo / country.is / Cloudflare против точки, где трафик
  физически входит в сеть. Расхождение = сайты видят пользователей «не там».
- **Фаервол** — ufw; `na_filter` загружен и в автозагрузке (если нет — покажет,
  что сработал сейфти-таймер и когда); взведённый сейфти; фильтр служебных
  портов; лимиты `na_filter` на один IP против пика соединений (за CGNAT
  оператора сидят сотни абонентов) и срабатывания SYN-лимита; баны na_filter и
  CrowdSec, под которые попали IP сегодняшних клиентов; порты вне реестра,
  открытые без фаервола.
- **Логи** — ошибки конфига `logrotate` (дубли станз), `compressoptions` в
  кавычках (zstd их не понимает — логи не сжимаются), падения самой ротации с
  последней ошибкой, гигантский текущий лог, бессрочное хранение.
- **Нода** — контейнеры и их имена, связь с панелью и netbird, свежесть образа
  ноды против Docker Hub, Xray (отказы и частые ошибки за час), фолбэк Reality →
  `nginx.sock`, маскировка (настоящий TLS-запрос к своему 443 с SNI: валидный
  сертификат и страница), location в nginx без инбаунда (заготовка или лишний),
  `SNI_VERIFICATION` в compose против контейнера, версия nginx.
- **Сертификат** маскировки и XHTTP/gRPC — срок; тот ли сертификат отдаёт nginx
  (он держит файл по симлинку и после продления без рестарта отдаёт старый);
  живо ли автопродление: таймер certbot, `deploy_hook` на рестарт nginx и ключ
  Cloudflare. Глобальный ключ (email + api_key) ловится заранее — продление с ним
  падает, а видно это только в день истечения. Исправление спросит API-токен
  зоны скрытым вводом, перепишет ini и продлит.
 
Каждая строка — ✓ / ▲ / ✗. В конце — меню починки: список того, что скрипт может
исправить сам, с пометкой о простое. После исправления меню возвращается к этому
же списку (сделанное помечается ✓), а не в главное меню:
 
```
▶ Можно починить скриптом
    1) ✓ сделано  Выключить ufw (na_filter остаётся единственным фаерволом)  — без простоя
    2) Порты 2222 — только для IP панели (подскажет, кто сейчас подключён)  — без простоя
    3) Исправить compressoptions и дожать несжатые логи (в фоне, низкий приоритет)  — без простоя
    4) Пересоздать контейнер ноды по compose (SNI_VERIFICATION=true), обрыв ~10 с  — короткий обрыв
    5) Перезагрузить сервер (обновились: libc6)  — перезагрузка — сними ноду с балансировки
 
    a) Починить всё, что ещё не сделано
    n) Починить всё, кроме location в nginx (заготовки под gRPC/XHTTP)
    s) Только то, что без простоя
    r) Провести аудит ещё раз
    0) Выйти в главное меню
Номера через пробел или буква:
```
 
Буквы работают и в русской раскладке (`ф`, `т`, `ы`, `к`).
 
`location` в nginx, за которым пока нет инбаунда, — не ошибка: его часто
оставляют заготовкой, чтобы включить gRPC/XHTTP в панели и сразу получить рабочий
маршрут без рестарта nginx. Аудит показывает такой location как информацию, а
убрать его можно отдельным исправлением; пункт `n` чинит всё остальное, не трогая
nginx. Выбранное выполняется в
порядке: сначала без простоя, потом с коротким обрывом, перезагрузка — последней
и с отдельным подтверждением; «Починить всё» спросит подтверждение, если в
списке есть обрыв или перезагрузка. Где у исправления есть
свой пункт меню (фаервол, порты панели, MTU, nginx), аудит зовёт именно его —
со всеми вопросами, бэкапами и откатами этого пункта.
 
Сервером не лечится и остаётся подсказкой: зависания ВМ и CPU steal (хостер),
GeoIP (хостер), кривые маршруты (хостер), сертификат, память/нагрузка,
буферы UDP и прочий тюнинг ядра (пункт 2), отказы Xray.
 
Свои sysctl (таймаут conntrack, выключение IPv6) аудит пишет в
`/etc/sysctl.d/99-zz-nodeforge.conf`, резолвер — в
`/etc/systemd/resolved.conf.d/nodeforge-dns.conf`.

## Шаги в панели Remnawave
 
Конфиг Xray в Remnawave единый и пушится на все ноды, поэтому часть шагов
**нельзя автоматизировать с ноды** — скрипт делает серверную часть и подсказывает,
что доделать в панели:
 
- **После пункта 6 (RU-блокировка)** — в разделе *Xray Config* заменить блоки
  `outbounds` и `routing` на JSON, который печатает скрипт, и сохранить.
- **После пункта 7 (Логи)** — в *Config Profile* ноды добавить блок `log` с путями
  `/var/log/remnanode/access.log` и `/var/log/remnanode/error.log`, иначе логи не
  появятся.

## Безопасность
 
- **В репозитории нет секретов.** Пароли, SSH-ключи, ключи netbird и т.п. вводятся
  при запуске через `read` и нигде не сохраняются (в историю shell не попадают).
- **Бэкапы и откат.** Правки `sshd_config`, `nginx.conf`, `docker-compose.yml`,
  сетевых конфигов делаются с резервной копией и проверкой (`sshd -t`, `nginx -t`,
  `docker compose config`, `ifquery` / `netplan generate`); при ошибке изменения
  откатываются.
- **Один фаервол.** `na_filter` (nftables) — единственный владелец портов; ufw
  выключается, потому что установщики нод включают его с «запретить всё».
- **Сейфти-таймер.** `protect` взводит таймер: без подтверждения через 5 минут
  `na_filter` удаляется и выключается из автозагрузки — чтобы не потерять доступ.
  Переподключение по SSH таймер **не** снимает. Скрипт в конце спрашивает, работает
  ли вход в новом окне, и снимает таймер только после «да»; затем проверяет, что
  фаервол загружен и в автозагрузке.
- **Служебные порты.** Порт ноды и порт агента Beszel закрыты для всех, кроме IP
  панели: своя nft-таблица на хуке `prerouting`. Не на `input`, потому что netbird
  в nftables-режиме вставляет `iifname "wt0" accept` в начало всех input-цепочек.
- **MTU меняется со страховкой.** Если после смены связь пропадёт, через 3 минуты
  прежний MTU вернётся сам.
- **NAT-VPS.** Если у провайдера внешний SSH-порт проброшен на внутренний `:22`
  (общий IP, «выделенного IP нет»), **не меняйте SSH-порт** — иначе проброс
  перестанет работать и вы потеряете доступ.
- **Внешние скрипты.** Пункты 13 и 14 (кроме встроенного аудита) запускают
  сторонний код с других доменов. Запускайте осознанно.

## Обновление
 
Меню → пункт **15**. Скрипт скачает свежую версию из репозитория и перезапустится.
Либо просто запустите команду из раздела «Запуск» ещё раз — она всегда тянет
актуальную версию.

## Лицензия / ответственность
 
Скрипт предоставляется «как есть», без гарантий. Вы запускаете его на свой страх и
риск; перед применением на боевом сервере проверьте, что делает каждый пункт.
